# Contributing to Agxium

This repository is the public issue, feedback, roadmap, and backlog hub for Agxium.

## Before opening an issue

1. Search existing open and closed issues.
2. Use the closest issue form.
3. Keep one problem or request per issue.
4. Include enough information to reproduce or understand the request.
5. Remove all sensitive or private information before submitting.

## Good bug reports

Include:

- affected Agxium product or surface;
- platform/device when relevant;
- app or integration version when known;
- clear expected behavior;
- clear observed behavior;
- minimal reproduction steps;
- screenshots only when they contain no private information.

Do not guess the technical root cause unless you have verified evidence. Symptoms and reproducible facts are more useful than speculation.

## Feature requests

Describe:

- the problem or workflow that needs improvement;
- who benefits;
- the desired outcome;
- any important constraints.

## Public/private boundary

Agxium implementation repositories may be private. Maintainers may create a private engineering issue after triage. Public reports must not contain private source, infrastructure details, secrets, credentials, raw production payloads, customer data, payment information, or verification evidence.

## Issue lifecycle

A public report can move through these outcomes:

- **Needs information** — more detail is required.
- **Accepted** — valid work or investigation is required.
- **Duplicate** — an existing report already tracks it.
- **Not planned** — valid request but not currently planned.
- **Not reproducible** — available evidence is insufficient to reproduce the problem.

Accepted engineering work is tracked internally while this issue remains the public reference.
